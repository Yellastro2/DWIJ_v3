# Автоматический офлайн плеера

Реализовано в исходниках 2026-10-21. Gradle, тесты и воспроизведение на устройствах агентом не запускались.

## Включение

`OfflinePlaybackPolicy` в application-scoped `PlayerRepository` считает **окончательные**
сетевые отказы элементов очереди. Android вызывает handler из `AndroidPlaybackRecovery`
после load retries/watchdog; desktop — из `recoverAttempt` после начальной попытки и трёх retry.
Существующие бюджеты времени сохранены. Три отказавших позиции подряд включают офлайн
**до auto-next**; callback возвращает true и забирает переход у движка.
Повторы callback одной позиции не увеличивают счётчик. Новая пользовательская очередь
сбрасывает серию. Ручной skip, пауза и отмена сами не являются отказом.

Три секунды фактического продвижения позиции сбрасывают серию. READY не достаточно;
скачки позиции и время на паузе не засчитываются. После включения офлайна локальный успех
его не выключает. Состояние не сохраняется на диск и не зависит от экрана плеера.

Ошибки авторизации, 404/429, формата и локального хранения не считаются отсутствием сети.
`TrackCacheRepository` сохраняет DataError до уведомления читателя; `VkHlsRelay` сохраняет
структурированную причину upstream отдельно от loopback 502. Платформенный network/timeout
используется как fallback, когда источник не успел вернуть свою причину.

## Очередь и аудио

Исходный состав хранится отдельно. `toOfflinePlaybackTrack` выбирает готовый ЯМ-файл,
локальный экземпляр либо VK bundle/полный кеш через `offlinePlaybackUri`. Частичный кеш
не участвует. При наличии локальной версии отказавшая песня получает её; иначе выбирается
следующий доступный элемент в порядке движка. Отказавший уже в офлайне элемент исключается
до новой очереди/восстановления сети, чтобы не образовался бесконечный цикл.

Сетевые предзагрузки и автоматическое продолжение ЯМ-волной выключены.
`WaveRepository` отменяет наблюдение/refill при включении офлайна и возобновляет его
для очереди волны после восстановления; поздняя партия не публикуется в офлайне.
Android data source,
desktop reader и VK resolver/fetch дополнительно запрещают новые сетевые чтения старых URI.
Если ничего доступного нет, очередь движка очищается: Play/гарнитура не запускают старую
сетевую очередь. В плеере слева от индикаторов источника отображается значок офлайна.

## Возврат сети

Один probe выполняется параллельно переходу между песнями с минимумом 15 секунд между
проверками. При остановке/пустой очереди проверки продолжаются. Общий бюджет — 8 секунд,
по 3,5 секунды на доступные в исходной очереди ЯМ/VK. Успех любого сервиса достаточен:
это политика доступности аудио, а не доказательство доступности всех провайдеров.

ЯМ получает свежую ссылку и один байт через `StreamingAudioSource` с действующим SDK/прокси;
VK запрашивает свежую запись API и байт HTTPS-ресурса через транспорт relay. Кеш не считается
сетевым успехом. Запоздалый probe другой пользовательской очереди отменяется/игнорируется.

После успеха `replaceQueueKeepingCurrent` возвращает полный состав вокруг текущего
локального элемента. Android сохраняет сам MediaItem, desktop — MediaPlayer и попытку,
обновляя её индекс. Звук и позиция не перезапускаются. Если локальной очереди не было,
полная очередь восстанавливается на паузе, без неожиданного автозапуска.

## Проверка после сборки

- Три сетевых отказа после всех прежних retry: четвёртой обычной сетевой попытки нет.
- Ошибка → ошибка → три секунды музыки → ошибка: серия начинается заново.
- 401/403/404/429, повреждённый файл, ручные skip/pause не включают офлайн.
- ЯМ готовый файл, локальный MediaStore и полный VK HLS/MP3 работают без сети; частичный VK исключён.
- Пустой/вытесненный кеш не вызывает бесконечного повтора; Play не возвращает сеть.
- Возврат сети сохраняет позицию, паузу и текущий звук; следующая песня доступна онлайн.
- Быстрый выбор другой очереди во время probe не возвращает старую очередь.

`OfflinePlaybackPolicyTest` покрывает порог, дедупликацию, READY/seek, сброс прогрессом,
новую очередь и обязательное сетевое подтверждение выхода. `OfflinePlaybackQueueTest`
проверяет перехват четвёртого запуска, возврат позиции, пустой кеш и восстановленную очередь
без dTracklist. Интеграционные проверки плееров остаются обязательными.
