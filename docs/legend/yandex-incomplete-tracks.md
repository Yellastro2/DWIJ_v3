# Неполные записи треков Яндекс Музыки

Наблюдение 2026-10-24: пользовательский лог `2026-10-24_01-36-35.log`, время
01:36:37, содержит успешный HTTP 200 для POST `/tracks`, после которого декодирование
`YaTrack` упало из-за отсутствующего `title` у `result[31]`. Скриншот радиального
меню содержит такую же ошибку класса `YaTrack`, но без пути JSON. Полного тела ответа
нет: удаление трека или конкретная причина отсутствия поля не доказаны.

В SDK идентификатор остаётся обязательным. Отсутствующие `title`, `available`, `artists`
и `albums` имеют безопасные значения: пустая строка, false и пустые списки. Последние
три случая — защитная обработка, а не подтверждённый этим логом формат ответа.
Неверные типы и отсутствие ID по-прежнему возвращают ошибку, а записи с ID сохраняют
порядок списка. Это применяется к пакетному `/tracks` и вложенным трекам плейлиста.

В приложении трек без названия не считается доступным для сетевого воспроизведения,
даже если пришло `available=true`. При сохранении Room сохраняет старые название,
артистов, обложку и длительность, обновляя отметку проверки и доступность. Новая запись
получает подпись «Недоступный трек». Готовое локальное аудио по-прежнему можно играть.
Последующий полный ответ заменяет заглушку обычными метаданными.

Код: `yaMusicSdk/.../entities/YaTrack.kt`, `shared/.../data/entities/dYaTrack.kt`,
`shared/.../data/dao/dTrackDao.kt`. Регрессии: `TrackApiTest`, `PlaylistApiTest`,
`YandexIncompleteTrackTest`, `DailyPlaylistPlaybackTest`. Сборка и тесты агентом не запускались.
