# Контекст очереди и смешанные треклисты

`dTracklist.yandexWaveSeed()` явно разрешает ЯМ rotor. По умолчанию null:
внутренние, локальные и VK-списки не отправляются в музыкальное API ЯМ.
Серверные ЯМ-плейлисты используют `playlist:uid_kind`, станции — station ID,
seed-объекты трека/артиста — `track:id` и `artist:id`. В `PlayerRepository`
больше нет перечня исключаемых классов при завершении очереди. `WaveRepository`
тоже отклоняет контекст без seed; null-контекст по-прежнему запускает личную волну.

`MixedTracklistEntry` содержит Song и MusicSource происхождения рекомендации.
`MixedTracklist` хранит снимок этих элементов и выдаёт песни для playQueue;
принимает только уникальные Song.id, чтобы происхождение оставалось однозначным
при shuffle и фильтрации недоступных элементов. Дубли нужно разрешить до создания.
Внутренняя смешанная подборка конечная и не является серверным ЯМ-плейлистом.

`originOf(songId)` возвращает источник сущности в текущем треклисте.
Он независим от PlaybackTrack.source: рекомендация VK может играть из локального
файла либо ЯМ-экземпляра. FullPlayerUiState.queueOrigin берётся из этого контекста,
большой плеер показывает Я / VK / Л рядом с мультисурсом; неизвестное происхождение
не заменяется догадкой по аудиоисточнику.

## «Всё сразу» и «Подборка» (2026-10-07)

HomeMusicSource.All доступен на главной; третья карточка «Подборка» запускает
MixedRecommendationPlayback. Плейлисты и треки подключены отдельно (см. ниже), общий поиск/каталог
показывают статус без обращения к отдельному сервису под видом общего режима.

По нажатию параллельно загружаются playlistOfTheDay ЯМ и audio.getRecommendations
VK. Метаданные обоих списков регистрируются в общем индексе Song. Недоступные
ЯМ-треки без кеша исключаются. alternateRecommendationSongs собирает уникальные
пары ЯМ → VK до конца короткого списка, одноисточниковый хвост не добавляется.
Нераспознанные совпадения между сервисами автоматически не удаляются.
Для каждой песни предпочитается экземпляр исходного сервиса в снимке очереди;
постоянное предпочтение пользователя в БД не меняется.

При ошибке любого запроса новая очередь не запускается. Повторное нажатие
заблокировано до завершения, смена VK-сессии отменяет принятие результата.
Перед запуском останавливается наблюдение ЯМ-волны. preserveQueueOrder запрещает
shuffle/repeat этой очереди, не меняя сохранённых настроек обычного воспроизведения.
После запуска открывается большой плеер с индикаторами происхождения Я/VK.

Тесты MixedTracklistTest и MixedRecommendationOrderTest добавлены;
Gradle и runtime-проверка агентом не запускались.

## Общая фонотека «Треки» (2026-10-20)

Карточка «Треки» в «Всё сразу» открывает `AllTracksRoute` в отдельном маршруте
`all-tracks`. Используются те же источники, что в отдельных разделах:
`TracklistModel` с `OBJECT_TYPE_TRACKLIST` для ЯМ (уникальные треки личных
плейлистов, включая лайки), `VkPlaylistModel` с `VK_ALL_TRACKS` для VK,
`LocalMusicRepository.songs` для видимых локальных файлов. Общий индекс всех
известных Song не используется как фонотека: в нём бывают поисковые результаты.

`AllTracksModel` объединяет списки без ограничения длиной короткого источника.
Уже связанные записи объединяются по `Song.id`; неподтверждённые совпадения
не сливаются. `LibraryShuffleOrder` назначает случайный ранг один раз за жизнь
маршрута. Догрузка добавляет новые песни в случайные позиции, сохраняя взаимный
порядок старых. Обновление метаданных и возврат из плеера не тасуют список заново.
Сортировка выполняется на `Dispatchers.Default`. Сначала показываются готовые
данные отдельных источников; медленный или недоступный источник не скрывает остальные.

Выбранная строка запускает снимок показанной очереди по `Song.id`, а не по индексу,
который мог измениться при догрузке. `LibraryTracklist` сохраняет происхождение
песен и не задаёт seed ЯМ; обычные shuffle/repeat плеера доступны. Предпочтения
экземпляров песен не меняются. Контекстные операции источников в общую сетку
не добавлены. Обновление жестом обновляет ЯМ/VK и разрешённую локальную библиотеку.
Разрешение на локальные файлы запрашивается через отдельный локальный раздел.

`LibraryShuffleOrderTest` проверяет полноту объединения, связанные дубли,
стабильность порядка при догрузке и удаление исчезнувших песен. Сборка, тесты
и воспроизведение требуют проверки пользователем; Gradle агентом не запускался.

## «Скачанные» (2026-10-20)

Четвёртая карточка главной называется «Скачанные» и доступна для ЯМ, VK и
«Всё сразу». Маршрут `downloaded-tracks/{downloadSource}` фиксирует фильтр
источника при входе. `DownloadedTracksModel` берёт метаданные из полного индекса
Song, затем оставляет только реально сохранённые экземпляры: непустые постоянные
ЯМ-файлы и готовые VK-bundle. Это включает одиночные загрузки и треки, удалённые
из плейлистов. Обычный LRU-кеш и файлы MediaStore не входят в раздел.

Результат сортируется по названию; объединённая Song с двумя сохранёнными
источниками занимает одну строку. Изменения Room и `localStorageRevision` ЯМ/VK
обновляют список. Жест обновления и возврат на экран повторно проверяют файлы.
Чтение индекса, проверка файлов и сортировка выполняются на IO, музыкальные API
для наполнения экрана не вызываются. VK offline-метаданные индексируются при
старте приложения существующим `indexSavedTracks()`.

Перед запуском файлы перепроверяются. Снимок очереди содержит только сохранённые
экземпляры выбранного источника: предпочтение онлайн-версии из Room не приводит
к сетевому воспроизведению другой версии. Постоянное предпочтение в Room не
меняется. `DownloadedTracklist` не задаёт seed ЯМ и сохраняет обычные shuffle/repeat.

`DownloadedTracksTest` проверяет фильтры, связанные дубли, отдельные загрузки,
исчезновение файлов и выбор сохранённого экземпляра. Gradle, тесты и проверка
офлайн-воспроизведения на Android/desktop агентом не запускались.
