# ВК Музыка: первый сценарий

## Подключение

`vkMusicSdk/` — независимый Kotlin/JVM SDK (Android и desktop, JVM 11).
Он не зависит от shared, Android, JavaFX или yaMusicSdk. Shared подключает его через
`api(project(":vkMusicSdk"))`; оба приложения получают его через shared.

- `VkApiClient`: token-based POST, отмена HTTP вместе с coroutine, версия 5.282;
  audio.search, getSearchSuggestions, catalog.getAudio/getSection, audio.add/delete.
- Дополнения по vkpymusic: audio.getById, пагинация плейлистов/треков,
  рекомендации. Каталог пока доступен сырым JsonElement; UI каталога VK не реализован.
- `VkOAuth`: OAuth Маруси из README LavaSrc, без клиентского секрета и cookies.
- `VkHlsRelay`: ограниченный текущим воспроизведением loopback-сервер для VOD HLS;
  relative URI, master playlist, AES-128, смена ключей, sequence/explicit IV,
  MAP и BYTERANGE. Нет перекодирования; поддержка контейнера зависит от плеера.

## Вход и поиск

1. Настройки → ВК Музыка → «Войти в VK через Марусю».
2. После входа скопировать полный URL страницы `oauth.vk.com/blank.html`.
3. Вернуться в приложение, вставить URL, нажать «Завершить вход».
4. Callback проверяется по HTTPS origin/path (oauth.vk.com или oauth.vk.ru) и совпадению state,
   если он присутствует. При явной ручной вставке отсутствие state допустимо (формат из LavaSrc).
   До сохранения выполняется
   audio.search с полученным токеном. Ошибка не заменяет прежнюю сессию.
5. Главная → Поиск → источник «ВК Музыка» → запрос → нажатие на трек.

Для этого первого сценария URL возвращается вручную: автоматический callback
через WebView/deep link не реализован. OAuth state переживает пересоздание экрана;
URL с токеном не сохраняется в saved state. Токен не выводится в логи.
Поле показывает ссылку обычным многострочным текстом (3–6 строк) с переносом длинного URL.
Цвета кнопок, отключённых состояний и label заданы явно для тёмной карточки.
Разбор отклонённого адреса возвращает конкретную причину: неверный URL/origin,
нет части после #, нет токена, повреждённые параметры, отказ VK или несовпадающий state.
Логи `[completeVkAuthorization]` сообщают эту причину либо факт принятия ссылки
и наличие/совпадение state; сам URL, токен и OAuth error_description не логируются.

Android хранит VK в отдельном зашифрованном SharedPreferences `vk_protected_session`,
исключённом из backup/transfer; Windows — отдельный DPAPI `vk-session.bin` рядом с
Яндекс-сессией. Удаление VK-входа не удаляет Яндекс-вход.

## Воспроизведение

`VkMusicRepository.play` запрашивает свежий URL через audio.getById и создаёт
временный Song с TrackInstance.Vk и составным id `vk:owner_id_audio_id`.
В Room трек не записывается. MusicSource.VK сохраняется до платформенного плеера;
ни Яндекс-feedback, ни Яндекс-prefetch, ни Rotor по завершении не запускаются.

HLS URL переписывается relay, ключи и подписанные upstream URL остаются в памяти.
Android подключает media3-exoplayer-hls и разрешает cleartext только для 127.0.0.1;
JavaFX получает обычный локальный m3u8 без AES-тегов. Новый выбор заменяет relay
после передачи очереди плееру; переход к другому источнику и завершение application scope закрывают ресурсы.
Прямой HTTPS-аудиофайл передаётся плееру без relay.

Обложки используют общий disk/memory cache с namespace vk-track, но независимую
загрузку HTTPS без Яндекс-прокси и преобразования URL.

## Границы первого теста

Плейлисты, лайки и каталог VK не подключены к UI. Их API доступны в SDK.
Кнопки разделов VK на главном экране ведут к поиску; сетка плейлистов VK показывает
сообщение о текущей доступности через поиск. Сохранения треков VK, объединения
с другими источниками и восстановления VK-очереди после смерти процесса пока нет.

owner_id, POST токена, безопасная API-ошибка, пагинация, AES/IV/смена ключа и HTTP range.
Агент Gradle/сборку/тесты не запускает по AGENT.md. Пользователь 2026-10-02 предоставил
лог запуска desktopApp:run и скриншоты карточки: desktop дошёл до интерфейса,
но ручная ссылка была отклонена до проверки Music API. Первоначальный код требовал
state безусловно и скрывал причину отказа; конкретный URL пользователя не предоставлен.
После исправлений UI/разбора нужны новый запуск и повторный вход.
Реальный музыкальный доступ, HLS и воспроизведение Android/Windows пока не подтверждены.

треков подряд, seek, паузу, конец одиночной очереди и возврат к Яндекс-треку.
