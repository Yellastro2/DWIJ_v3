# Журналы сессий приложения

## Назначение

Приложение сохраняет журналы текущего процесса, чтобы пользователь мог сам
экспортировать диагностический ZIP. Ни Android-, ни Windows-версия не отправляет
его автоматически.

Реализации находятся в `AppSessionLogStore` для Android и
`DesktopSessionLogStore` для Windows.

## Android

- Запись `logcat` текущего процесса запускается в `yApplication` до инициализации общего графа.
- Файлы находятся во внутреннем каталоге `files/app-session-logs`.
- Имя сессии содержит дату и время запуска приложения.
- Хранятся текущая и предыдущая сессии.
- В начало новой сессии копируются последние 300 строк предыдущей.
- При превышении 5 МБ начало текущего файла отрезается примерно наполовину.
- Буфер сбрасывается на диск каждые пять секунд и принудительно перед созданием архива.
- Каталог исключён из облачного backup и переноса данных устройства.
- Системные, WorkManager и OEM-теги из списка `excludedTags` отбрасываются без учёта регистра;
  `WM-WorkerWrapper`, `Choreographer` и `View` сохраняются как полезная диагностика фоновых задач
  и производительности интерфейса.

Заголовок содержит версию приложения, сведения об Android и устройстве, случайный `sessionId`
и `ANDROID_ID`. Архив является приватной диагностикой: приложение не отправляет его автоматически,
но содержимое становится доступно выбранному пользователем получателю.

## Windows

- Файлы находятся в `%LOCALAPPDATA%\DWIJ\logs`.
- Записываются все события, проходящие через общий `YamLogger`, и stacktrace необработанных
  исключений. Системные Windows-логи не захватываются, поэтому фильтр по OEM- и системным тегам
  на Windows не нужен.
- Хранятся текущая и предыдущая сессии; в новую копируются последние 300 строк предыдущей.
- При превышении 5 МБ начало текущего файла обрезается примерно наполовину.
- Каждая строка сразу сбрасывается на диск, чтобы хвост журнала переживал аварийное завершение.
- Заголовок содержит версию, сведения о Windows, Java, случайный `sessionId` и стабильный
  `installationId`. Идентификатор генерируется один раз и хранится в уже существующем `settings.properties`.

## Экспорт

Действие «Диагностика → Экспортировать» вызывает платформенный `shareLogs`. В архив входят
два последних файла сессий.

На Android метод создаёт `cache/log_exports/dwij-app-session-logs.zip`, получает временный `content://` URI
через `FileProvider` и открывает системный выбор приложения-получателя.

На Windows открывается обычный диалог сохранения с именем `dwij-app-session-logs.zip` и каталогом
`Загрузки` по умолчанию. Архив сначала пишется во временный файл рядом с целевым, затем
атомарно перемещается. Если имя занято, добавляется числовой суффикс, а существующий файл не
перезаписывается.
