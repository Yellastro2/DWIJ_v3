# Журналы сессий приложения

## Назначение

Android-приложение сохраняет строки `logcat` текущего процесса, чтобы пользователь мог вручную
отправить диагностику через системное меню «Поделиться». Запись запускается в `yApplication`
до инициализации общего графа приложения.

Основная реализация находится в
`app/src/main/java/com/yellastrodev/dwij/util/AppSessionLogStore.kt`.

## Хранение

- Файлы находятся во внутреннем каталоге `files/app-session-logs`.
- Имя сессии содержит дату и время запуска приложения.
- Хранятся текущая и предыдущая сессии.
- В начало новой сессии копируются последние 300 строк предыдущей.
- При превышении 5 МБ начало текущего файла отрезается примерно наполовину.
- Буфер сбрасывается на диск каждые пять секунд и принудительно перед созданием архива.
- Каталог исключён из облачного backup и переноса данных устройства.
- Системные, WorkManager и OEM-теги из списка `excludedTags` отбрасываются без учёта регистра;
  `WM-WorkerWrapper`, `Choreographer` и `View` сохраняются как полезная диагностика фоновых задач
  и производительности интерфейса.

Заголовок содержит версию приложения, сведения об Android и устройстве, случайный `sessionId`
и `ANDROID_ID`. Архив является приватной диагностикой: приложение не отправляет его автоматически,
но содержимое становится доступно выбранному пользователем получателю.

## Отправка

Действие «Диагностика» на Android-экране настроек вызывает платформенный метод `shareLogs`.
Он создаёт `cache/log_exports/dwij-app-session-logs.zip`, получает временный `content://` URI
через `FileProvider` и открывает системный выбор приложения-получателя. В архив входят два
последних файла сессий.

Desktop-версия не показывает это действие: возможность объявляется через
`SettingsPlatform.canShareLogs`.
