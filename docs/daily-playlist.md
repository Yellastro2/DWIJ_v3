# Плейлист дня в приложении

В `WaveGridRoute` вторая плитка после «Моей волны» — «Плейлист дня».
При каждом входе на экран и при обновлении жестом параллельно запускаются
загрузка станций и `DailyPlaylistPlayback.load()` → SDK `playlistOfTheDay()`.
Снимок `PlaylistDetails` хранится только в Compose `remember`, без восстановления
через saveable или БД. Ошибка/отсутствие подборки показывается в подписи плитки.

Нажатие передаёт загруженные треки в `DailyPlaylistPlayback.play()`.
Создаются временные Song/TrackInstance с отдельными `daily:` идентификаторами;
реальный ID ЯМ сохраняется для воспроизведения. Нет обращений к репозиториям
песен/плейлистов, DAO, сохранения метаданных или связей track-playlist.
Обычный аудиокеш плеера продолжает работать. Загрузка рекомендации сама по себе
не меняет играющую очередь; новое нажатие запускает свежий снимок.

Запуск живёт в application scope и не отменяется переходом к плееру.
Перед запуском прекращается наблюдение Rotor и подгрузка его следующей пачки.
Контекст `DailyPlaylistTracklist` не является dYaPlaylist/dYaWave;
PlayerRepository не запускает волну при его TrackListEnd. Shuffle/repeat работают
как у обычной конечной очереди, поэтому включённый пользователем repeat-all
может повторять тот же список.

## Проверка вручную

1. Открыть «Волны»: день второй; дождаться количества треков или сообщения ошибки.
2. Запустить день после «Моей волны»: играют треки дня, Rotor больше не пополняет очередь.
3. При выключенном повторе последний трек завершает список без запуска волны.
4. Убедиться, что в фонотеке не появился плейлист или новые связи с его треками.
5. Перезапустить приложение и открыть «Волны»: выполняется новый API-запрос.
6. Проверить отказ сети и обновление жестом; станции и день обрабатывают ошибки раздельно.

Gradle и UI-проверка агентом не запускались. Тесты преобразования находятся в
`shared/src/desktopTest/kotlin/com/yellastrodev/dwij/playback/DailyPlaylistPlaybackTest.kt`.
