# Фиксированная тема интерфейса

`shared/src/commonMain/kotlin/com/yellastrodev/dwij/ui/theme/DwijTheme.kt`
задаёт единственную тёмную Material3-схему из `DwijColors`. Тема ОС и динамические
цвета Android не выбирают палитру Движа.

- Android: `MainActivity.onCreate` оборачивает всё `setContent` в `DwijTheme`,
  включая диалог настройки ссылок вне `DwijApp`.
- Desktop: `Main.kt` оборачивает содержимое окна, включая `DesktopWindowFrame`.
- `MaterialTheme.colorScheme` задаёт фон и контрастный контент поверх него:
  обычные меню/диалоги используют светлые текст и иконки; кнопки, поля, ошибки,
  границы и поверхности тоже получают цвета нашей палитры. Отключённые состояния
  компонентов Material3 используют стандартную прозрачность поверх наших цветов.
- `LocalContentColor` по умолчанию белый: обычный `Text`/`Icon` вне Material3-поверхности
  тоже не получает стандартный чёрный цвет.
- `ObjectScreen.ObjectTopBar` задаёт фон меню через `containerColor`, согласованный
  со схемой, вместо фонового модификатора поверх стандартного контейнера.

Для обычного текста достаточно наследования темы. Явный `color`/`colors` нужен
для особого оформления или контента на нестандартном фоне; такой цвет переопределяет
общую тему. При добавлении отдельного Compose-корня или самостоятельного preview
его также нужно оборачивать в `DwijTheme`. Нативные системные окна не входят в Compose-тему.

Реализовано 2026-11-02 в исходниках. Проверены точки подключения, дифф и расчёт
контраста пар основных текстовых ролей (не менее 4.5:1 для непрозрачных цветов).
Gradle, сборка и запуск агентом не выполнялись.

После сборки проверить на Android со светлой и тёмной темой ОС: меню VK-плейлиста
«Сохранить локально»/«Обновить», отключённые пункты, меню трека, диалоги и поля ввода.
Их цвета должны оставаться одинаковыми при переключении темы ОС. На desktop
проверить те же shared-экраны и меню.
